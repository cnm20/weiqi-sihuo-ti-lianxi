## 四、可复现步骤（新环境）

```bash
npm install
npm run dev                 # 开发 http://localhost:5173（或见 package.json）
npm test                    # Vitest 28 例
npm run build               # tsc + vite build → dist/
npm run preview             # 预览构建产物
npm run test:e2e            # Playwright 21 例（自动拉起 dev :5199；PWA/离线需先 build，preview :5188）
npx playwright install --with-deps   # 若浏览器缺失（本项目用 PLAYWRIGHT_BROWSERS_PATH=_tools/.playwright-browsers）
```

题库再生成（改判读或补题后）：
1. 编辑 `_tools/candidates/review-records.json`（或先跑审读子代理）
2. `node tools/rebuildChecklist.ts`（判读清单）
3. `node tools/buildFinalPuzzles.ts`（生成 100 题 TS；仅 reviewed+published 入库）
4. `node --experimental-strip-types tools/validateAudits.ts`（证据闸门）
5. `node --experimental-strip-types tools/resortBands.ts`（仅 100 题时执行全库复排）
6. 重新 `npm test` / `npm run build` / `npm run test:e2e`

> 说明：`dist/`、`_tools/candidates/puzzles.json`（转换中间体）、KataGo 本地文件均为
> gitignore 不入库；从零重建题库需先取得原谱语料（gogameguru/go-problems，见 docs）并跑转换工具。

## 五、诚实声明（未宣称完成 / 留白）

- **难度语义**：九档（9级～1级）与 1段 均为「练习参考难度」，按结构代理（主解用户手数→树规模→根候选）排序，非段级认证。
- **判读依赖人工围棋阅读**：GGG 谱多数无显式目标词，方向判定依据谱面 + 注释 + 主解事实综合得出；
  证据闸门 PASS=72 / WARN=29，WARN 条目均附 notes 人工证据，未自动判定为对错。
- **SKIP 7 条不入库**（easy-01/03/11/30/37/44/59：劫/双活/开放对杀/主解未闭合），台账记录原因供回溯。
