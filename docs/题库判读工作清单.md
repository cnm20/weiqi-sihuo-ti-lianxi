# 题库判读工作清单

> 每题入库须满足：全树规则引擎验证 ✓（自动）、主解可达 ✓（自动）、
> 中文目标（做活/杀棋）与要点判定（谱面证据）、难度与档位归属、来源记录。
> 判读结果写入 `_tools/candidates/review-records.json`（content-audited 后经复核置 reviewed）。
> 正式题库只含 reviewed 且 published=true 的题（整档满 10 后由 buildFinalPuzzles 发布）。
> 本清单三个来源池列表由 `tools/rebuildChecklist.ts` 按磁盘 + review-records **自动重建**，
> 请勿手工改动各行标记/计数（改 review-records.json 后运行该工具即可）。

## 判读工具与口径（2026-09-07 更新）

- 转换器已改为**方向感知成功判读**（`tools/convertSgf.ts successJudgeFor`）：
  只有注释表明【用户方】达成目标（Correct / 用户自己做活 / 对方死）才算成功终点；
  谱中"White's already alive / alive in seki"等"对手仍活"注记不再被误当作黑棋成功。
- 审核支持工具：`tools/genOnePacket.ts`（审读包）、`tools/branchMap.ts`（分支级注释视图）、
  `tools/mainlineFacts.ts`（主解提子事实）、`tools/endState.ts`（终局棋群与眼位）、
  `tools/auditSuccessLabels.ts`（成功叶误标审计）、`tools/mineGoalEvidence.ts`（目标证据挖掘）。
- **来源文本约束（诚实声明）**：GGG 谱注释普遍只有 "Correct"，多数 easy 题无目标词，
  故"做活/杀棋"须逐题依据谱面+规则引擎+注释综合判读；无把握一律保持 needs-review。
  机器验证可选增强：KataGo(Eigen CPU) 已就绪于 `_tools/katago/`（含 b6c96 模型，
  本地使用、不入库，`.gitignore` 已排除）；analysis 模式接入待后续轮次完成。
- **防虚标证据闸门**：`tools/validateAudits.ts` 对每条 content-audited/reviewed 记录
  检查 goal 是否具备机器可查证据（根注释/成功叶/失败叶目标词或主解黑提白）；
  无证据记录输出 WARN（须逐题阅读复核），不自动判错——语言级正反语义由人工把关。
