# 题库审核流程与台账说明（内容工程）

> 目标：10 档 × 10 题 = 100 题「正式题库」。题目须满足：
> 有中文目标（做活/杀棋）、解题要点、可回放正解、典型错误变化、来源记录、难度归属，
> 且答案树逐分支经规则引擎验证。**未逐题审核确认的题目不得宣称题库完成。**

## 数据流

```
GGG SGF (weekly-go-problems)                    （pro 出题，CC BY-NC-SA 4.0）
   │ tools/analyzeCorpus.ts                      全树合法+交替校验（421/422 通过）
   ▼
tools/convertSgf.ts                              转“用户视角答案树”
   │  成功终点=谱中明确“Correct/活/死”语义叶（自动候选）
   │  规则：不存在自动把“未确认/未收录”当作错误
   ▼
_tools/candidates/puzzles.json                   （转换候选，reviewStatus=needs-review）
   │ tools/verifyPool.ts                         （结构自洽+主解重放 420/422）
   ▼
_tools/candidates/review-records.json            ← ★ 逐题人工审核记录（本题库核心台账）
   │ 每条记录：goal / goalTextCN / keyPointCN / titleCN / 确认错误分支 / notes / reviewedAt
   ▼
tools/mergeReviews.ts → src/data/puzzles.generated.ts   （仅“reviewed”题进入正式题库）
```

## review-records.json 记录字段（按来源文件为键）

| 字段 | 含义 |
|---|---|
| `titleCN` | 中文题名，如「角部做活：先紧气」 |
| `goal` | `live`（做活）或 `kill`（杀棋），无法判定记 `unknown` 且**不可标记 reviewed** |
| `goalTextCN` | 题面目标句，如「黑先，使角上黑棋做出两只眼」 |
| `keyPointCN` | 解题要点（一句话） |
| `confirmedWrong` | 逐点确认的典型错误（[x,y]），用于“回答错误”反馈 |
| `notes` | 审核依据与备注（谱面/变化说明） |
| `reviewedAt` | 审核完成时间 |

## 审核判定口径（重要）

1. **做活 / 杀棋的判定**依据：对题面与主解变化做围棋语义阅读后给出；
   凡无法可靠判定目标方向的题目，一律保持 `needs-review`，绝不猜测。
2. **成功终点**：以 GGG 谱注释明确标注（Correct / lives / is dead / White is dead 等）为准；
   仅当该叶对应用户手达成目标。转换器自动标注仅作候选，审核者复核。
3. **错误变化**：只录入审核中确认的典型错误分支；答案树中其余未收录合法走法由
   `unlistedPolicy` 处理（默认 neutral，不计成绩、不显示错误图）。
4. **难度/分档**：结合谱面技术要点、变化深度、候选迷惑性与对方抵抗综合判定，
   参考谱自带 easy/intermediate/hard 粗分；等级标注为“练习参考难度”。
